# Migration Risk Register
## Project: Skill Mantra Academy / Skill Thinker Platform

---

## 1. Risk Evaluation Matrix

| Risk ID | Risk Description | Severity | Likelihood | Impact Area | Mitigation Strategy & Safeguards |
|---|---|:---:|:---:|---|---|
| **R01** | **Accidental Production Database Modification or Reset** | CRITICAL | Low | Database (Neon) | 1. Never run destructive DDL (`DROP TABLE`, `TRUNCATE`, `ALTER TABLE DROP COLUMN`) during migrations.<br>2. Work strictly against an isolated local/test database or a separate Neon development branch.<br>3. Require explicit manual approval before applying any schema migration.<br>4. Baseline Alembic against existing schema (`alembic stamp`) rather than applying fresh DDL. |
| **R02** | **Password Hash Verification Incompatibility (bcryptjs $\rightarrow$ Python)** | HIGH | Medium | Authentication | 1. The existing application uses `bcryptjs` with prefix `$2a$` or `$2b$`.<br>2. In Python, use `passlib` with `bcrypt` or standard `bcrypt` / `argon2-cffi`.<br>3. Verify compatibility on real password hashes with test harness.<br>4. Support dual-verification: verify existing bcrypt hashes seamlessly; rehash to Argon2id upon successful authentication. |
| **R03** | **Next.js Server Component Direct DB Read Left Behind** | HIGH | Medium | Security & Architecture | 1. Thoroughly inventory all 40+ Server Components importing `src/lib/db/*`.<br>2. Build typed API client (`src/lib/api/*`) for both Server Components and client hooks.<br>3. Introduce static check / linter rule forbidding `@/lib/db` imports in `src/app/` once migration is complete.<br>4. Remove `src/lib/db.ts` only after all components compile cleanly against the API client. |
| **R04** | **Cross-Tenant Data Leakage (Multi-Tenancy Breach)** | HIGH | Medium | Application Security | 1. Enforce tenant filtering in FastAPI dependency injection (`get_current_college_admin`, `get_current_trainer`, `get_current_student`).<br>2. Do not trust client query parameters.<br>3. Execute automated negative security test suites probing cross-college and cross-batch resource access. |
| **R05** | **Session Cookie & CORS Misconfiguration** | MEDIUM | High | Integration | 1. During local development, frontend (port 3000) and backend (port 8000) run on different ports. Cookies need `SameSite=lax`, `credentials: 'include'`, and properly configured CORS `allow_origins`.<br>2. For production, configure Next.js rewrites or a reverse proxy (e.g., Nginx or Caddy) so `/api/v1/*` routes through the same origin, eliminating CORS issues entirely. |
| **R06** | **Bulk Student CSV Import Memory / Timeout Bottleneck** | MEDIUM | Medium | Performance | 1. Roster files may contain 500-1000 student records.<br>2. Avoid sequential 1-by-1 database inserts.<br>3. Use SQLAlchemy `insert().values([...]).on_conflict_do_update()` bulk queries inside a single database transaction.<br>4. Implement row-level validation returning structured error reports if specific rows fail. |
| **R07** | **Exam Question Leakage / Cheat Vulnerability** | HIGH | Low | Examination Integrity | 1. In the target backend `GET /api/v1/student/exams/{id}`, explicitly exclude `correct_option_index` and `explanation` from the Pydantic response schema.<br>2. Prevent duplicate exam submissions using an atomic database constraint `UNIQUE(assessment_id, student_id)`.<br>3. Perform score calculations strictly on the backend. |
| **R08** | **Session Invalidation Inability (Stateless JWT Risk)** | MEDIUM | Low | Security | 1. Implement database-backed session storage (`user_sessions` table) storing hashed tokens.<br>2. Support instantaneous revocation upon logout, password change, or admin deactivation. |
| **R09** | **Downtime During Cutover** | MEDIUM | Medium | Operational Availability | 1. Both Next.js backend and FastAPI backend can query the same Neon PostgreSQL schema concurrently during the phased rollout.<br>2. Frontend pages can be migrated module-by-module (Auth first, Colleges second, Batches third, Portals fourth).<br>3. Zero downtime cutover with immediate rollback capability. |
| **R10** | **Database Connection Exhaustion on Serverless PostgreSQL** | MEDIUM | Medium | Database Performance | 1. Configure SQLAlchemy connection pooling with connection recycling (`pool_recycle=300`, `pool_pre_ping=True`, `pool_size=10`, `max_overflow=20`) to play nicely with Neon's pooled endpoint.<br>2. Avoid opening new connections per request handler. |
